# Paper Version Comparison and Blueprint Impact

Date: 2026-08-28  
Compared files: `paper.pdf` (old) and `2608.25512v1.pdf` (new, v1)

## Executive conclusion

The new PDF is a structural revision, not a proofreading-only revision.  It keeps the
same title, authors, motivating problem, two composability dimensions, Cordis case study,
and overall Sections 1--8, but changes the formal core substantially.  The old PDF is 88
pages; the new PDF is 92 pages.  The frozen graph and blueprint in this repository are
anchored to the old PDF SHA-256 (`4d48478d...a49db97f`), while the new PDF has SHA-256
`390775dbc9debdcf2ed1b076eed013387ca057630be3cb594617b2b742e48cf0`.

**Recommendation:** treat the new PDF as a new formalization baseline.  Existing Lean
work can be retained as an implementation experiment, but paper-ID references and the
dependency graph must be remapped before claiming conformance.  Under the requested
default, P9 should be a paper-sync gate and should complete before any new proof wave.

### Important semantic additions in the new PDF

1. An effect iterator yields `(new state, inverse, continuation)` and is recursively
   witnessed.  A plain effect is only the one-step embedding.
2. Coeffect operations act on a key's value and carry their own inverse and outcome;
   context-mediated iterators can perform operations and provisions in stages.
3. Observational equivalence is generated by the operations available to an observer,
   lifted from values to stores, states, maps, products, options, and recursive iterators.
4. Independence quantifies over the reach-closed transformation monoids of iterators,
   including both forward maps and yielded inverses, plus inverse/continuation stability.
5. Coeffect commutativity is witnessed at keys and is used to derive independence of
   mediated computations; this is stronger and more explicit than merely commuting two
   top-level effect compositions.

## Blueprint and dependency-graph alignment

### Already aligned (retain)

- Relation-parametric laws, explicit observation relations, and no quotient execution
  carrier (`BD-EQUIV`, ADR-01/06).
- Per-state selected inverses, iterator/failure separation, ranked termination, and the
  error/boundary/prefix-undo failure result (`BD-ITER`, ADR-05, G6).
- Scoped coeffects as a separate boundary (`BD-SCOPED`) and the distinction between the
  authoritative dependent coeffect store and the Toy registry.
- The P2--P7 layering and the existing `PiRel`/`RelSpec` proof abstractions as code-level
  implementation choices.

### Required changes to the planning model (recommendations)

1. **P9-first synchronization gate.** Add a P9 wave (without changing this report's
   scope) that records the new PDF hash, extracts a new numbered inventory, and produces
   an old-ID to new-section/title crosswalk.  No new theorem should be labelled paper-
   faithful until this gate passes.
2. **Versioned graph, not in-place mutation.** Preserve H03 as the old baseline and add a
   versioned H03-v2 graph for `2608.25512v1.pdf`.  Recompute direct edges for the new
   definitions; do not shift IDs mechanically because inserted iterator and observation
   material changes downstream statement dependencies.
3. **Split the new Section 3.4.** Add explicit graph nodes for iterator reach/monoids,
   iterator independence, coeffect-operation independence, witnessed coeffects, and
   mediated-independence.  Connect them before global recovery, transposition, and
   confluence results.
4. **Promote iterator nodes earlier.** In the new source, iterator definitions occur in
   Section 3.1.3 and are used by later coeffects and components.  The current blueprint's
   P4 placement is executable-sensible, but its paper traceability must point to the new
   Section 3.1.3 rather than old Section 4.3.2.
5. **Make observation a prerequisite of effect laws.** New Definitions 31--39 make
   operation-induced equivalence and relation-respecting inverses constructional.  Keep
   P1/P5 relation layers before any claim of independence or confluence; do not treat
   observational transport as a post-hoc corollary.
6. **Re-audit theorem premises.** New recovery/independence results quantify over
   iterator reach, yielded inverses, continuations, common definedness, and outcomes.
   Existing graph edges that mention only D8/D19 or a top-level effect must be expanded
   to include these premises.
7. **Keep extensions out of the kernel claim.** The new Section 4.4 does not license an
   unqualified runtime-verification claim.  Retain the blueprint's R0 boundary and mark
   asynchronous/scoped implementation refinements as separate evidence obligations.

## P9-first execution order

1. Freeze old artifacts and hashes (H03/H04 remain immutable).
2. Build the v2 inventory and crosswalk: sections, formal-item numbers, equations,
   theorem premises, and renamed concepts.
3. Generate a v2 dependency graph and identify nodes with no current Lean counterpart.
4. Reclassify existing Lean declarations against v2 (`faithful`, `strengthened`,
   `renamed`, `deferred`, or `not applicable`).
5. Only then schedule proof work.  The current P1--P8 code can be tested against the
   crosswalk, but should not be silently relabelled as a v2 proof.
